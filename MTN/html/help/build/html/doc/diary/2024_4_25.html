'获取ftp目录列表，检查目录是否已存在
Public Function ftp目录列表(ByVal 创建的目录 As String)
Dim st As Stream
Dim sr As StreamReader
Dim 目录列表 As String
Try
    ftp请求对象.Method = WebRequestMethods.Ftp.ListDirectory
    ftp响应对象 = CType(ftp请求对象.GetResponse, FtpWebResponse)
    st = ftp响应对象.GetResponseStream
    sr = New StreamReader(st, Encoding.UTF8)
    目录列表 = sr.ReadToEnd
    Dim 所有目录() As String = 目录列表.Split(vbCrLf.ToCharArray(), StringSplitOptions.RemoveEmptyEntries)'这里为修改内容
    For Each 目录条目 As String In 所有目录
        Dim 目录名 = 目录条目.Trim().Substring(目录条目.LastIndexOf("/") + 1).ToLower()'这里为修改内容
        If 目录名 = 创建的目录.ToLower() Then
            Return "目录已存在"
        End If
    Next
    ftp响应对象.Close()
    Return "ok"
Catch ex As Exception
    Return ex.Message
End Try
End Function

测试结果具体不详，好像是成功了。出现了一个小问题就是计算分的线程结束的时候，由于使用了递归函数所以会多次返回结束 解决方法是使用一个计算器，每次计算完就加一，然后判断计算器是否等于0，等于0就结束。 其原理是。 在原始方案中，您提到直接在递归函数的最后设置一个全局变量，如 判断线程 = True，来标记递归函数的结束。然而，这样的做法存在问题，因为递归函数可能会有多层嵌套调用。在递归过程中，每当进入一个递归层级时，都会执行一次设置 判断线程 = True 的操作。这意味着在递归尚未完全结束时，可能已经有一个或多个较浅层级的递归调用提前设置了 判断线程 为 True。这样，当您在外部检查这个变量时，可能看到的是某个中间状态，而非真正的递归结束状态。

使用计数器的运行机制

为了解决这个问题，我们引入了一个计数器 recursiveCallsCount，用于跟踪当前处于活动状态的递归调用数量。当递归函数开始执行时，计数器加1；当递归函数结束时，计数器减1。这样，计数器的值反映了当前有多少个递归层级还在执行中。

具体过程如下：

递归调用开始：

当首次进入 获取所有目录 函数时，计数器从0开始，增加到1。这表示有一个递归调用正在进行。 遍历当前目录下的文件并处理。 遍历当前目录下的子目录，并对每个子目录再次调用 获取所有目录 函数。 递归调用深入：

对于每个子目录，计数器再次增加1，表示又有一个新的递归调用开始。 子目录下的文件处理和子子目录递归调用重复上述过程。 递归调用结束：

当某个子目录的递归处理完成时，其对应的递归调用结束，计数器减少1。 同理，当所有子目录的递归调用都结束时，当前目录的递归调用也结束，计数器再次减少1。 递归完全结束：

最终，当最初的递归调用（即最外层调用）结束时，计数器会减至0。此时，没有其他递归调用在进行中，说明递归函数已完全结束。 在计数器减至0的时刻，更新 UI 文本和 判断线程 变量。 总结来说，通过使用计数器，我们能够精确地跟踪递归调用的层次和状态，确保在所有递归调用都完成时才标记递归函数的结束。这样就避免了因递归过程中各层级提前设置变量而导致的误判问题。希望这个解释有助于您理解这个方法的工作机制。如果您还有疑问或需要进一步说明，请随时告知。 那么最后的程序是
